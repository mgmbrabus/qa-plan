|---|---|---|
| **Java 17 (LTS)** | Язык написания тестов | Промышленный стандарт для enterprise-автоматизации, строгая типизация, длительная поддержка. |
| **Selenide** | UI Framework | Обертка над Selenium WebDriver с лаконичным API, встроенными умными ожиданиями (Smart Waits) и автоматическим закрытием браузера. Упрощает работу с динамическими элементами. |

## 3. Перечень необходимых разрешений, данных и доступов

1. **Доступ к тестовому стенду (Staging/Dev контур):**
   * Выделенный стенд с тестовой базой данных и отключенной рассылкой реальных заявок/уведомлений клиентам. Это необходимо для безопасного прогона позитивных тестов с отправкой формы.
2. **Письменное разрешение на проведение нагрузочного/автоматизированного тестирования:**
   * Согласование с администраторами инфраструктуры, добавление IP-адресов тестовых машин в whitelist (белый список) для исключения блокировок системами WAF, Cloudflare и reCAPTCHA.
3. **Требования и документация:**
   * Спецификация валидации полей формы (маски ввода, регулярные выражения, ограничения по длине строк).
4. **Тестовые атрибуты в верстке:**
   * Наличие или согласование добавления уникальных селекторов (`data-test-id` / `data-testid`) на ключевые элементы и поля формы.

## 4. Перечень и описание возможных рисков при автоматизации

* **Риск 1: Попадание тестовых заявок в боевую CRM-систему (спам лидами).**
  * *Снижение риска:* запуск тестов с отправкой формы строго на изолированном staging-окружении либо мокирование сетевых запросов (Network Interception / Mock Server).
* **Риск 2: Ложные срабатывания WAF / блокировка по IP / появление капчи.**
  * *Снижение риска:* внесение IP раннеров в белый список, отключение капчи на тестовом стенде.
* **Риск 3: Падение тестов из-за частых изменений верстки или A/B-тестирования.**
  * *Снижение риска:* применение паттерна Page Object Model (POM), использование стабильных семантических селекторов (`data-testid`), согласование фиксированного состояния лендинга для тестов.
* **Риск 4: Нестабильность тестов (Flaky tests) из-за анимаций и сетевых задержек.**
  * *Снижение риска:* использование встроенных интеллектуальных ожиданий Selenide вместо явных `Thread.sleep()`.

## 5. Перечень необходимых специалистов для автоматизации

Для реализации данного проекта не требуется раздувать команду разработки:

* **Инженер по автоматизации тестирования (QA Automation Engineer / SDET) — 1 специалист.**  
  Специалист обладает всеми необходимыми компетенциями ручного тестировщика (анализ требований, составление тест-кейсов и тест-дизайн) и автоматизатора (написание фреймворка, Page Objects, тестов и конфигурация CI/CD пайплайна). Внешние команды фронтенда и девопсов привлекаются только в формате разовых инфраструктурных консультаций.
